# 维护与后续计划

首版维护对象为单播协议子集及其公开 API。bug 修复优先于扩展协议。版本遵循 SemVer：0.x 可能调整 API，但应记录迁移；补丁版本保持现有有效报文及公开调用兼容。

## 受理问题

请提供工具链版本、目标平台、最小 MoonBit 调用、报文字节、peer、时间序列与预期结果。协议问题应标注 RFC 章节。测试报文不要包含真实凭据或敏感业务负载。

## 近期维护

1. 扩展真实 IPv6 UDP 互通与 Windows/Linux 计时行为测试；完成前不宣称已验证。
2. 调研公开可维护的单调时钟适配，使 Native 默认驱动减少系统回拨影响。
3. 收集真实调用者反馈，增加符合当前子集的回归报文，持续检查错误选项与队列回压。
4. 跟踪 MoonBit/async 公共 API 更新，升级在分支完成全量验证后发布新版本。

Observe、Blockwise 和安全层可作为后续版本独立设计议题，需协议与测试预算、互通证据以及 API 兼容说明。它们不是首版“即将完成”的能力。性能优化应先取得真实环境与测量方法，不提交未测量性能数字。

## 开发与发布流程

先复现问题 → 新增行为/不变量测试 → 修复 → 格式/类型/测试/构建/示例/互通检查 → 更新接口和 CHANGELOG → 发布候选包 → 独立消费验证 → 版本标签与发布说明。

保持真实提交日期，不改写已公布历史补数量。公开仓库中的 Issues 记录实际维护议题；有需要审阅的分支变更时使用 PR。内存去重无持久性、无安全层、未验证 IPv6 网络等限制会持续保留在 README 与协议矩阵。
